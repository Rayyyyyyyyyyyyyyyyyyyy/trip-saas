## Why

Trip Runtime promises that travelers can use their existing itinerary during travel without repeatedly reopening the source. The 2026-09-07 full-document review and executable probes found that faithful unknown values can block confirmation, valid undated content can disappear from Result, and Canonical import accepts invalid date/time semantics; completed implementation task counts therefore do not establish the product outcome.

## What Changes

- Make source-absent facts, preserved ambiguity and genuine conflicts distinct across interpretation, Review, confirmation, persistence and presentation; users may retain supported unknowns without inventing dates or places.
- Share authoritative calendar/time/reference validation across Draft, confirmed JSON import and stored reads/writes; align nullable schema and TypeScript contracts.
- Give every confirmed entity one complete primary placement, including trip-level undated information, while retaining relationships, notes and exact source actions.
- Preserve minimum non-content source identity/locator provenance with an explicit schema compatibility decision; never persist raw Review evidence.
- Version the benchmark assessment rules around faithful unknowns, source-supported facts and semantic preservation; separately measure original parser quality, Review recovery and Result usability.
- Verify CSP delivery against the actual current static deployment entry and retain Golden Viewer reliability, browser-local key boundaries and bounded failure recovery.
- Consolidate the three previous implementation changes as historical, explicitly unaccepted at the external gate. Transfer every open task and all eight review findings to this change, with evidence links and no checked-off-as-passed substitutions.
- Update current document ownership/status and missing baseline capability records without rolling back the approved newspaper UI or promoting pending implementation to shipped behavior.
- Remove the unaccepted alternate-model retry surface, keep every bounded retry on one configured exact Gemini model, and reuse the already validated prepared source when the selected Markdown is unchanged.
- Replace provider-code-only Review unblocking with source-linked candidate checks that preserve partial dates and verbatim ambiguous clock expressions, reconcile obsolete findings after explicit user corrections, and keep unsupported precision blocking.
- Keep source-supported month/day labels readable in Result without inventing a year, prevent persistent Result controls from overlapping the date rail, and present unavailable relative images as understandable attachment placeholders instead of raw Markdown syntax.

## Capabilities

### New Capabilities

- `faithful-markdown-acceptance`: Outcome-based acceptance for a true Markdown-to-confirmed-mobile-Result journey, including reproducible scoring, recovery, usability and evidence-preserving change handoff.
- `deployed-static-security`: CSP policy delivery and verification for the actual static entry, with no implicit Hosted Delivery enablement.

### Modified Capabilities

- `trip-semantic-interpretation`: Preserve absent facts and ambiguous expressions without compulsory completion, title/name rewriting or unsupported inferred precision.
- `local-canonical-trip`: Permit supported unknown values through confirmation/reload, enforce semantic validation at every trust entry and retain minimal provenance safely.
- `evidence-backed-trip-review`: Permit faithful unknowns, focus conflict correction and validate before committing while measuring correction burden.
- `deterministic-result-placement`: Extend complete unique primary placement to undated entities and mixed dated/undated relationships.
- `markdown-source-intake`: Preserve validated source/evidence identities across downstream retry of an unchanged selected source while retaining fresh workflow ownership.

## Impact

Expected implementation areas: `src/domain/trip`, `src/domain/source`, `src/features/review`, `src/features/result`, `src/features/import`, `src/integrations/gemini`, `src/persistence`, `src/app`, static deployment/CSP files and corresponding tests. The existing source adapter, deep interpreter, application workflow, provider transport and frozen visual ownership remain the baseline. No new production dependency is required by this proposal.

Current evidence: [full review](../../../temp/validation/full-document-review-2026-09-07.md), [root probes](../../../temp/validation/reviewer-root-probes-2026-09-07.md), sanitized artifacts under `temp/validation/`, and [official model selection research](../../../temp/gemini-model-selection-research-2026-09-08.md). Benchmark #001 has not passed; exact `gemini-3.5-flash` is retained as failed historical evidence, the 2026-10-07 user decision retains exact `gemini-3.5-flash` as the current candidate instead of the previously researched 3.8 candidate, and production has no accepted no-override default.

Non-goals: Hosted Delivery implementation, spreadsheet/PDF intake, Canonical JSON export, accounts, multi-trip, recommendations, replanning, generalized Today/runtime, automatic provider fallback, new analytics service or an untested offline guarantee. V0.1/V0.2 and later runtime remain separately gated roadmap work. Performance and weak-network checks collect evidence; broader caching or asset architecture changes require findings rather than speculative expansion.
